# Contributing

Balanced OKRs is a developing set of practical writing materials. Contributions should clarify the framework, challenge assumptions, or add grounded examples.

## Working conventions

- Edit Markdown directly; prefer descriptive headings, short paragraphs, and readable tables.
- Keep the pamphlet concise and self-contained. Expand detailed arguments in the book.
- Use **Objective**, **Key Result**, and **Guardrail** for the three parts of a Balanced OKR. Put optional diagnostic analysis under the Guardrail it helps evaluate.
- Label hypothetical thresholds and examples rather than presenting them as measured results.
- Cite sources for empirical claims, historical claims, and named studies. Distinguish our proposed practice from established OKR guidance.
- Discuss meaningful counterexamples and the administrative cost of the approach.
- Use pull requests for substantive edits so design decisions remain reviewable.

## Initial review questions

1. Is the definition of a non-compensating guardrail clear and operational?
2. Are we adding useful constraints, or merely multiplying metrics?
3. How do we distinguish discovery OKRs from execution OKRs?
4. What level of evidence should justify a leading indicator?
5. How do we handle delayed outcomes that outlive a quarterly OKR?
6. How should shared capacity and cross-team dependencies be represented?
7. What minimum process can a small organization reasonably sustain?
